# Edge Image Captioning 🖼️ → 💬

Ever needed image captions but couldn't afford to ship every photo off to some giant cloud model? That's the problem this project tackles. It runs a full vision-language model — a ViT encoder paired with a GPT-2 decoder — entirely on CPU, thanks to ONNX Runtime and INT8 quantization. No GPU required, no cloud calls, just a compact microservice that spits out captions.

## What it does

You send it an image over HTTP, and it sends back a text description of what's in the picture. Behind the scenes:

1. **ViT** (Vision Transformer) looks at the image and turns it into patch embeddings.
2. GPT-2's **cross-attention layers** attend to those image features — this fusion is pretrained on COCO Captions (the `nlpconnect/vit-gpt2-image-captioning` checkpoint), so the captions are trained, not random.
3. **GPT-2** generates the caption one token at a time, using the image as its "context."
4. The whole model gets traced to ONNX and dynamically quantized down to **INT8**, so inference runs fast on an ordinary CPU.

The inference loop (`infer_onnx.py`) is deliberately simple — just greedy decoding with a max sequence length of 32 tokens, stopping when the model emits its end-of-sequence token. No fancy beam search, no frills — just low-latency captioning.

## Project layout

```
├── app.py                  # FastAPI microservice (the /api/v1/caption endpoint)
├── config.py               # Model names, image size, ONNX paths
├── export_onnx.py          # Traces PyTorch → ONNX FP32, then quantizes to INT8
├── infer_onnx.py           # EdgeCaptionEngine: loads ONNX + runs autoregressive decoding
├── requirements.txt
├── models/
│   ├── encoder_decoder.py  # ViTCaptioner: ViT + projection + GPT-2
│   └── quantize.py         # INT8 dynamic quantization helper
├── pipeline/
│   └── preprocessor.py     # Image preprocessing + token decoding
└── weights/
    ├── model_fp32.onnx     # Generated by export
    └── model_int8.onnx     # What actually gets served
```

## Getting started

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. Export the model to ONNX (FP32 → INT8)

```bash
python export_onnx.py
```

This pulls the pretrained `nlpconnect/vit-gpt2-image-captioning` fusion (a ViT encoder and a GPT-2 decoder with trained cross-attention, fine-tuned on COCO Captions), traces the combined model, and compresses the result. In practice this shrinks the FP32 model (~914 MB including external data) down to roughly **232 MB of INT8 weights — about a 75% reduction**. The final INT8 model lands at `weights/model_int8.onnx`.

### 3. Run the API

```bash
python app.py
```

or

```bash
uvicorn app:app --host 0.0.0.0 --port 8000
```

### 4. Ask for a caption

```bash
curl -X POST http://localhost:8000/api/v1/caption \
  -F "file=@your_photo.jpg"
```

You'll get back something like:

```json
{
  "filename": "your_photo.jpg",
  "caption": "a dog sitting on the grass in a park"
}
```

There's also a health check at `/health` if you want to poke at it, and interactive docs at `/docs` courtesy of FastAPI.

## Serving details

The FastAPI app loads the ONNX session **once** at startup (via the lifespan hook), so every request skips model-loading overhead. The runtime is tuned for edge conditions: CPU-only execution provider, capped at 2 intra-op threads, with all graph optimizations enabled.

## Why quantization matters here

Dynamic INT8 quantization shrinks the model by roughly 4× on weight size and typically speeds up CPU inference noticeably — especially on the small, thermally-constrained devices you'd actually deploy this kind of thing on. The `compress_to_int8` helper reports the exact size reduction when it runs.

To change the encoder/decoder pairing (say, a smaller ViT or a different decoder), just edit `config.py` and re-run the export script.

## Tech stack

- **PyTorch** — model definition and tracing
- **Hugging Face Transformers** — ViT + GPT-2 fusion (`nlpconnect/vit-gpt2-image-captioning`), image processor, tokenizer
- **ONNX / ONNX Runtime** — export, quantization, and CPU inference
- **FastAPI + Uvicorn** — the serving layer
- **Pillow** — image handling
